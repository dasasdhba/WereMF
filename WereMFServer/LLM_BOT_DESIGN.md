# LLM Bot 设计

## 目标

LLM 只负责提出玩家输入，WereMF CLI 继续作为唯一规则引擎，WereMFServer 继续负责权限、合法性校验、超时和回退。模型故障不得阻塞对局，也不得获得该席位本来不可见的信息。

## 第一阶段：裁决型 Bot

当前实现覆盖永久 Bot 和断线托管 Bot：

1. CLI 发出 request。
2. Server 根据接收者构造该 Bot 的可见上下文。
3. 通过 OpenAI 兼容 `POST /chat/completions` 请求模型返回 `{ "input": "..." }`。
4. Server 使用现有 `IsLegalTimeoutInput`、投票不可选集合等规则复核。
5. 合法则写入 CLI；超时、HTTP/JSON 错误或非法输入直接采用随机合法回退。

普通技能每个 request 调用一次，重抽调用一次。白天开始和真人发言会让每个存活 Bot 独立决定发言或沉默；投票开始及后续真实时间间隔会让其同时决定是否发言、是否提交一票或继续观望。一次思考至多提交一票，第二次机会必须留到后续思考，届时可以确认或改票；脚滑人可以选择 `b` 自爆。并发阶段最多同时请求四个 Bot，单个模型端点默认超时 15 秒。

模型会同时看到“投票阶段实际经过时间”和“扣除每票惩罚后的投票预算剩余时间”。定时思考按墙钟间隔触发，不按预算变化触发，因此投一票不会造成递归唤醒；预算临近截止是明确的投票决策变量。

## 上下文与隐私

每个请求包含：

- Bot 的本局编号和显示名称；
- 当前 API、请求文案和结构化 `data`；
- 最近的公开历史；
- 只属于该 Bot 的私密/逐玩家脱敏历史；
- 根目录 `design.txt` 去掉 Credits 后的完整玩法知识。
- 由服务器从该 Bot 的个性化权威状态与当前 `pending_skill_created` 映射直接提取的身份规则焦点；包括叶子二阶段身份和合虫复制身份。

不包含其他玩家隐藏身份、房主专属消息、原始全量 CLI 日志、其他 Bot 的私密历史或 API Key。状态快照已经过与浏览器相同的 `RedactedEnvelope` 脱敏。真实云模型仍会收到该 Bot 自己的身份、状态、公开聊天和玩家昵称，因此启用前应明确接受这一数据边界。

上下文按语义分层：本局模式、服务器确认的长期私密知识、稀疏记忆、最新权威状态、近期事件。吧主获知的脚滑人、脚滑人开局获知的身份、炮仙获知的队友、贤松获知的炮仙等私密事实由服务端从定向消息中提取并持续注入，不依赖模型主动记录；最新 `game_update_day/night` 是唯一权威现状；稀疏记忆只保存模型主动选择的、带可见事件来源的行动记录、公开承诺或未证实推断，不能覆盖当前状态。

## 发言与投票策略

- 默认沉默。投票本身已经是表态，不能为了活跃气氛而复述信息、寒暄或主持讨论。
- 只有提供新增信息或推导、明确被推出风险下的必要自保、临近截止拉票，或己方局面迫使其干扰时才发言；收到少量票本身不构成自保理由。模型必须显式返回 `speech_intent`，服务端只接受这些有限意图。
- 以存活为基本目标。除非收益明显、优势巨大或确有被票风险，否则不公开精确身份；受质问时可以沉默、只报阵营，或编造不与公开信息冲突的优势方身份。
- 叶子未暴露时按隐藏身份处理；已公开进入二阶段后不再伪装，优先制造白天减员。可以先投威胁较大的玩家，投票预算低于一分钟时跟进最可能被投出的目标。
- 重抽时谨慎保留炮仙和脚滑人等关键信息身份，除非存在明确且更高的策略收益。
- 真人或 Bot 消息采用约 3 秒防抖并允许相关 Bot 极简跟进，每个白天至多连续跟进 3 次；开场约等待 4 秒，连续 Bot 发言之间约隔 1.5 秒。带发言的投票立即提交，沉默投票随机延迟约 0.8–4.5 秒，避免同时刷屏。
- 投票请求不等待开场思考；投票开始后尚未发出的开场发言作废，由投票阶段思考接管。

## 名称

`bots_prefer.txt` 是主要名称池，`bots.txt` 是备选名称池。每个房间依次选择尚未被真人或其他 Bot 占用的名称；全部用完后回退为 `Bot N`。名称只影响显示和提示中的人格标识，不携带阵营或策略加成。

## 配置与观测

- `SILICONFLOW_API_KEY`：存在时启用。
- `SILICONFLOW_MODEL`：默认 `Qwen/Qwen3.5-4B`。
- `SILICONFLOW_BASE_URL`：默认 `https://api.siliconflow.cn/v1/`。
- `SILICONFLOW_TIMEOUT_SECONDS`：默认 15。
- `SILICONFLOW_BOT_THINK_SECONDS`：投票期间再次思考的墙钟间隔，默认 10。
- `--disable-llm-bots`：强制关闭。

`GET /api/health` 的 `llmStats` 只公开聚合计数：请求、API 成功、API 失败、通过合法性校验、被拒并回退、四类失败，以及连续失败、熔断截止时间、探测状态和熔断跳过次数。任意调用连续失败两次后全局熔断 60 秒，期满只放行一个探测请求；成功关闭熔断，失败重新计时。不得记录 API Key、完整提示词、模型原始回答或隐藏状态。

## 已知限制

- 4B 模型会收到完整规则和当前状态，但复杂多夜推理能力仍然有限。
- 当前公开历史和私密历史分别截取后组合，足以保证隐私，但还不是严格的统一时间线。
- 小模型可以保持沉默，但第一票尚未使用且场上连续一个思考间隔无人发言、无人投票时，服务端会随机提交合法非零首票，以规避半数弃票风险；第二票仍由后续思考确认或改票。模型连续两次调用失败、预算不足 60 秒或仅剩最后一次机会时也会提交合法随机票，最终仍有既有超时规则兜底。
- 稀疏记忆只在局内保留，重新开局会清空；服务端最多保留 12 条，并拒绝无来源、过长、重复或直接引用权威状态快照的候选。
- 现有合法性检查偏向格式和不可选集合；最终语义仍由 CLI 解析，任何遗漏都应以 CLI parse error 作为回归用例补入服务端校验。

## 后续路线

### 近期改进：结构化局势

每次技能、投票或发言决策都允许模型返回一个可选的 `memory_add`。模型先检查三类候选：自己的可核对行动、以后需要保持一致或可能被追问的公开说法、基于公开发言形成的未证实推测；技能或并发选择非 `0` 时默认记录自己的行动，发言内容涉及自己的行动、身份声明、承诺或推测时不得留空，只有沉默、单纯复述当前状态或只表达投票目标时才可填 `null`。它必须包含短文本、`kind` 和可见事件编号 `source_events`；服务端负责校验来源、去重、限量并注入后续上下文。服务器状态、资源、存活、投票和临时效果不进入 memory，自己的身份本身也不记录。
### 第四阶段：人格与策略

名称可绑定简短、无规则特权的人格参数，例如谨慎度、发言频率、风险偏好和是否倾向保留资源。人格不应绑定固定阵营，也不能跨局记住真人私密信息。

### 第五阶段：评测

固定种子批量运行随机 Bot、LLM Bot 和混合局，比较：

- 对局完成率、平均时长和 parse error 数；
- LLM 延迟、失败率、合法输出率和随机回退率；
- 各身份技能放弃率、资源浪费率和明显自伤率；
- 各阵营/身份胜率相对随机基线的变化；
- 隐私断言：任一提示不得出现其他席位的 `message_type: player_X` 私密消息。

评测日志只保留决策输入的脱敏摘要、最终候选、是否合法和回退原因；生产环境默认不保存完整提示词。

## 备用模型

通过 `LLM_FALLBACK_BASE_URL` 配置第二个 OpenAI 兼容端点；`LLM_FALLBACK_API_KEY` 可选，`LLM_FALLBACK_MODEL` 默认 `big-pickle`，超时与基础输出上限分别由 `LLM_FALLBACK_TIMEOUT_SECONDS`（默认 15）和 `LLM_FALLBACK_MAX_TOKENS`（默认 1024）控制。配置后两个模型并行请求，采用最先返回的有效结果；一方失败或被自身熔断时继续等待另一方，采用结果后取消仍在运行的请求。两个端点的失败计数和熔断状态彼此独立。

第二个模型接收与主模型相同的、按 Bot 视角脱敏后的上下文。健康统计公开并行竞速次数、第二端点获胜次数和嵌套的独立客户端聚合统计，不记录提示词、模型原始回答或密钥。
